## 0. 文档定位

### 0.1 目的

在需求 V1.0 已定的前提下，给出：

1. **技术选型结论与取舍理由**（为什么选、为什么不选）；
2. **系统架构与模块边界**；
3. **关键链路的实现细节**（扫描、索引、滑动播放、预加载、标记、剪切、权限）；
4. **性能/内存/存储预算与工程约束**；
5. **可排期的工作分解与风险清单**。

本文是研发与测试的技术基线；与需求冲突时以需求为准，技术冲突时以本文「决策记录」章节为准并走变更。

### 0.2 架构原则（不可妥协）

| 原则 | 落地含义 |
|------|----------|
| 本地优先 | 视频与标记不出设备；无账号、无云同步（V1.0） |
| SAF 优先 | 读写以 Tree URI / DocumentFile 为主，全盘权限仅作备选开关 |
| 硬解优先、软解兜底 | 流畅与续航优先；兼容性靠第二引擎，不是默认路径 |
| 播放列表 = 查询结果 | 滑动模式不另建「临时播放列表表」，以当前 Filter + Sort 的稳定有序结果集驱动 |
| 失败不删源 | 跨卷移动必须 copy 校验成功后再删；任务可重试 |
| 主线程零 IO | 扫描、缩略图、移动、元数据全部进 IO/Default 调度器 |
| 可观测 | 扫描进度、任务进度、播放器降级原因可在 Debug/任务页看到 |

### 0.3 关键技术挑战（必须先认清）

1. **深层级 + 5000+ 文件**：DocumentTree 递归遍历慢、URI 权限碎片化；
2. **类短视频垂直滑动**：多播放器实例、预加载与内存墙（≤500MB）；
3. **格式大杂烩**：单 ExoPlayer 不够，需双引擎编排；
4. **Android 分区存储**：剪切/删除在 Q+ 上行为分裂（MediaStore vs SAF）；
5. **标记与文件移动的身份连续性**：路径变了标记不能丢。

### 1.2 模块划分（Gradle 建议）

采用多 module，避免「单 app 巨石」导致编译与边界失控：

```
:app                    // Application、导航、DI 入口、权限编排
:core:model             // 纯 Kotlin 数据模型 / 枚举（无 Android 依赖）
:core:common            // Result、Dispatchers、PathUtils、扩展
:core:database          // Room Entity/DAO/DB、Migration
:core:datastore         // 设置、根文件夹偏好
:feature:library        // 视频库网格/列表、多选
:feature:filter         // 筛选面板、智能分类
:feature:player         // 滑动播放 + 传统播放壳
:feature:mark           // 标记/标签 UI 与用例（可并入 library，视人力）
:feature:task           // 任务列表 UI
:feature:settings
:domain                 // UseCase（Scan、Query、Mark、Move、Delete）
:data                   // Repository 实现、SAF、MediaStore bridge
:media:exoplayer        // ExoPlayer 封装
:media:vlc              // LibVLC 封装（可独立 AAR 依赖）
:media:thumbnail        // 缩略图管线
:media:engine           // PlayerEngine 路由（硬解→软解→外部）
:work                   // WorkManager Workers
```

> **MVP 裁剪建议**：人力 ≤2 人时可先 monorepo 单 module + 包结构分区，但 **包边界必须按上表物理隔离**，二期再拆 Gradle module。

### 1.3 应用进程与组件

| 组件 | 用途 |
|------|------|
| `MainActivity`（单 Activity） | Compose NavHost |
| `ScanWorker` | 全量/增量扫描 |
| `MoveWorker` | 批量剪切 |
| `DeleteWorker` | 批量删除（系统删除请求协作） |
| `ThumbnailWorker`（可选） | 空闲时补全缩略图 |
| 前台服务（可选） | 长时间剪切时提升优先级；V1.0 用 WorkManager + 通知即可 |

**不做**：多进程播放（复杂度过高，V1.0 收益不足）。

### 2.2 播放双引擎：为什么是 Exo + VLC，而不是单引擎

| 方案 | 优点 | 缺点 | V1.0 结论 |
|------|------|------|-----------|
| 仅 Media3 | 体积小、Google 维护、硬解优秀 | 老容器/怪编码弱 | 不够 |
| Media3 + FFmpeg 解码扩展 | 体积相对可控 | 自编译痛苦、授权与包体仍不小、老格式仍可能弱 | 备选二期 |
| Media3 + LibVLC | 兼容面最大、截帧可用 | **+20~30MB**、两套 Surface/生命周期 | **采纳** |
| 仅 VLC | 兼容强 | 列表预加载/多实例控制、Compose 集成不如 Exo 顺 | 不做主引擎 |

**包体积策略**：`media:vlc` 用 productFlavor 或动态特性模块可选；默认 release 含 VLC（需求已接受体积）。

### 2.3 minSdk / targetSdk

| 项 | 值 | 理由 |
|----|-----|------|
| minSdk | **26**（Android 8.0） | 覆盖主流；避免过多旧存储分支 |
| targetSdk | **35** | 跟进商店政策 |
| compileSdk | 35 | — |

Android 7 及以下用户占比低，且 DocumentTree/播放行为差异大，V1.0 明确不支持。

## 4. 数据层设计

### 4.1 身份模型（标记不丢的关键）

文件移动后 path/uri 会变，标记必须靠 **稳定身份** 重绑：

| 身份字段 | 稳定性 | 用法 |
|----------|--------|------|
| `id`（本地 PK） | 稳定 | 标记、进度外键 |
| `documentId`（SAF doc id） | 同树内相对稳 | 增量扫描匹配 |
| `mediaStoreId` | 系统索引存在时稳 | 删改协作 |
| `contentHash`（可选 P1） | 强 | size + 头尾采样哈希，用于移动后找回 |
| `absolutePath` / `treeUri` + `docUri` | 易变 | 展示与打开 |

**V1.0 重绑算法（移动成功后）：**

1. 任务项记录 `videoId`；
2. 成功写入目标后拿到新 `docUri`；
3. `UPDATE video SET uri=?, relativePath=?, absolutePath=?, parentSubPath=?, isMoved=1, markStatus=MOVED WHERE id=?`；
4. 标签关系表不动（仍挂 `videoId`）。

## 5. 文件访问与权限实现

### 5.1 权限矩阵

| 场景 | API 26–28 | API 29–32 | API 33+ | API 34+ |
|------|-----------|-----------|---------|---------|
| 读视频（若走 MediaStore） | READ_EXTERNAL_STORAGE | 同左 / 分区 | READ_MEDIA_VIDEO | 注意部分授权 |
| 读用户选中树 | SAF 即可 | SAF | SAF | SAF |
| 写目标目录 | SAF persistable | SAF | SAF | SAF |
| 删 MediaStore 项 | 直接或请求 | createWrite/DeleteRequest | createDeleteRequest | 同左 |
| 全盘管理 | — | — | MANAGE_EXTERNAL_STORAGE（备选） | 商店敏感 |

**V1.0 主路径：用户用 SAF 选根树 → `takePersistableUriPermission` → 全程 DocumentFile 递归。**  
MediaStore 用作：补元数据、删改请求、缩略图辅助，不是唯一真相源。

### 5.2 根文件夹选定流程

```
OpenDocumentTree
 → contentResolver.takePersistableUriPermission(uri, R | W)
 → 写入 root_folder
 → 入队 ScanWorker(FULL)
 → UI 观察 scan_progress（DataStore 或 DB 进度表）
```

更换根目录：

1. 提示「将重建索引」；
2. V1.0 策略：**清空该 root 下 video 相关数据**（或标记 is_missing 后全量替换）；标记跨 root 不迁移；
3. 释放旧 persist 权限（可选）。

### 5.3 递归扫描算法（核心）

**目标**：5000 文件 ≤60s（UFS 内部存储乐观值）；UI 不卡死。

```text
输入: treeUri, mode=FULL|INCREMENTAL
栈/队列 BFS:
  弹出目录 doc
  列出 children（DocumentFile.listFiles 或 query Children）
  对每个 child:
    if directory → push，记录相对 path
    if video by ext/mime → emit VideoDraft
  每 N 条（如 50）批量 upsert Room
  更新进度: scannedDirs, foundVideos
FULL 结束: 对 DB 中未触达的 video 标 is_missing=1（或删除）
INCREMENTAL: 用 document_id + date_modified + size 比对
```

**实现注意：**

1. **不要**在主线程 `listFiles`；
2. DocumentFile 在深树很慢 → 优先 `ContentResolver.query` on `DocumentsContract.buildChildDocumentsUriUsingTree`；
3. 扩展名白名单 + mime `video/*`；mime 空时仍认白名单；
4. 元数据（时长/分辨率）**不要**在扫描热路径全做完：  
   - 扫描阶段：路径、size、lastModified、ext；  
   - 异步 `MetadataEnricher` 队列补齐 duration/codec（限并发 2）；
5. 扫描可取消：`CoroutineWorker` + `isStopped`；
6. 进度：Notification + UI Flow。

**视频扩展名白名单（与需求对齐）：**  
`mp4,m4v,mov,mkv,webm,avi,wmv,flv,ts,m2ts,mts,3gp,mpg,mpeg,rmvb,rm,vob,asf`

### 5.4 相对路径计算

```text
rootDisplayName 可不入 path
relative = join(segments from root to file)
例: 2024/旅行/日本/day1.mp4
parent_sub_path = 2024/旅行/日本
depth = parent 段数
```

路径展示省略：`PathAbbreviator.abbreviate(path, maxChars=40)` → `2024/…/日本/day1.mp4`

## 6. 媒体引擎实现细节

### 6.1 统一抽象

```kotlin
interface PlayerEngine {
  val engineId: EngineId // EXO, VLC
  fun attach(surface: Any /* SurfaceView/TextureView/Compose */)
  fun load(media: MediaRef) // uri + mime + headers
  fun play(); fun pause(); fun seekTo(ms: Long)
  fun setSpeed(speed: Float)
  fun release()
  val events: Flow<PlayerEvent> // Ready, Error, Ended, Position
  fun selectSubtitle(track: TrackId?)
  fun selectAudio(track: TrackId?)
}

interface PlayerRouter {
  /** 按 hint / 历史失败 / 设置 选择引擎并在失败时 failover */
  suspend fun obtain(media: MediaRef, prefer: EnginePrefer): PlayerEngine
}
```

### 6.2 路由策略

```text
prefer = HARD_FIRST (默认):
  try ExoPlayer
    onError(decoder/source) → 记 play_engine_hint=VLC → 切 VLC 同 surface 策略
  VLC 再失败 → emit OpenExternal(media)
prefer = SOFT_FIRST: 直接 VLC
prefer = EXTERNAL: 不创建引擎，直接 Intent
```

**Failover 防抖**：同一 `videoId` 会话内 Exo 失败一次即本会话改 VLC，避免反复切换闪烁。

### 6.3 ExoPlayer 配置要点

- `ExoPlayer.Builder` + `DefaultRenderersFactory`（优先扩展渲染）；
- 本地 URI：`DefaultDataSource`；SAF content URI 直接支持；
- 关闭无用网络组件；
- 音轨/字幕：`TrackSelectionParameters`；
- 播完：监听 `STATE_ENDED` → 通知 SwipeCoordinator 下一首；
- HDR：跟随设备与 Media3 默认；
- **每个预加载实例独立 ExoPlayer**，禁止多页共用一个未复位的 player（状态极易乱）。

### 6.4 LibVLC 配置要点

- `LibVLC` 单例（native 重），`MediaPlayer` 可多实例但 **严格限制 ≤ 预加载数+1**；
- 选项示例：`--avcodec-skiploopfilter=4` 等按机型可调（进阶）；
- Surface：`AWindow` / `TextureView`；Compose 用 `AndroidView`；
- 截帧缩略图：独立短生命周期 MediaPlayer 或 libvlc media 解析 API；
- 释放顺序：stop → detach views → release player；LibVLC 进程级释放仅在 App 退出。

### 6.5 外部打开

```kotlin
Intent(ACTION_VIEW).setDataAndType(uri, mime).addFlags(FLAG_GRANT_READ_URI_PERMISSION)
```

失败 Toast + 标记「不支持」。

## 7. 短视频式滑动浏览（实现核心）

### 7.1 组件结构

```
SwipeBrowseScreen
 ├─ VerticalPager(pageCount = playlist.size, beyondViewportPageCount = 0/1)
 ├─ page(i) → VideoPage(
 │     playerHost: PlayerHost(pool.acquire(i)),
 │     overlay: TopInfo + BottomControls + MarkBar
 │  )
 ├─ GestureLayer（单击/双击/长按；与 Pager 纵向拖争夺优先级）
 └─ SwipeBrowseViewModel
       ├─ playlist: ImmutableList<VideoId> 或 Paging 窗口 + 绝对 index
       ├─ currentIndex
       ├─ markState
       └─ PlayerSessionCoordinator
```

### 7.2 播放列表如何与 5000 条共存

**问题**：不能把 5000 个 URI 全塞内存，又要 O(1) 上下滑。

**方案 A（推荐 V1.0）：稳定查询 + 窗口化 ID 列表**

1. 进入滑动时，对当前 Filter+Sort 执行一次 `SELECT id FROM video WHERE ... ORDER BY ...`；
2. 5000 个 Long 约几十 KB，可接受；若未来 5 万再改键集分页；
3. `currentIndex` 指向该 idList；
4. 上下滑 = index±1；加载 `video` 详情用 `dao.getById`；
5. 列表页点击第 k 项：需能映射到 idList 下标（同查询）。

**方案 B**：Paging 仅 UI，滑动用 `APPEND` 窗口——实现复杂，易出现「筛序不一致」，V1.0 不采用。

### 7.3 PlayerPool（预加载）

```text
参数 N = settings.preloadCount ∈ [1,3]，默认 1
池中最多持有 2N+1 个引擎实例（当前±N）

onPageSettled(index):
  keep = {index-N … index+N}
  release 不在 keep 的 player
  for t in keep:
    if 无实例: acquire → load(uri) → 仅 index 调用 play()
    其他: pause + seek(0) 或保留位置策略（V1.0：非当前一律 pause，seek 到 0 或上次进度）

大文件策略:
  size > 阈值（如 1GB）或 duration > 阈值:
    预加载页只 prepare 到 STATE_READY 的最低缓冲，不主动 seek 预热全片
```

**内存预算：**

| 项 | 预算 |
|----|------|
| 单 Exo 本地播放 | 经验 40–120MB 级波动（解码器/分辨率强相关） |
| N=1 → 约 3 实例 | 严格监控，超 500MB 则强制 N=1 并杀软解实例 |
| VLC 实例 | 通常更重 → **预加载默认只用 Exo；VLC 仅当前页 failover** |

**重要决策（写入实现规范）：**  
预加载层 **只创建 ExoPlayer**；LibVLC 仅在当前页 Exo 失败后接管，且同时全局最多 1 个 VLC 播放实例。这样内存与发热可控。

### 7.4 手势与冲突

| 手势 | 实现 | 与 Pager |
|------|------|----------|
| 垂直拖 | Pager 默认 | 主手势 |
| 单击 | `detectTapGestures onTap` 300ms 内 | 不禁用 Pager |
| 双击 | `onDoubleTap` → Mark KEEP | |
| 长按 | `onLongPress` → speed=2f，up 恢复 | |
| 水平拖 | 自定义：位移→seek ± | 用 `awaitPointerEventScope` 判断主导轴，水平主导时消费事件 |

## 10. 一键剪切（Move）实现细节

### 10.1 冲突策略

| 策略 | 行为 |
|------|------|
| RENAME | `name.ext` → `name (1).ext` |
| SKIP | 目标已存在则跳过，计失败/跳过 |
| OVERWRITE | 删目标再写入（高危，二次确认文案） |
| ASK | V1.0 可降级为进入前选死策略；逐文件 ASK UI 成本高 |

### 10.2 同卷 vs 跨卷

```text
resolveVolume(sourceDoc, targetDir):
  if 可 DocumentsContract.moveDocument → 优先 moveDocument（同 provider 树内最佳）
  else if 同存储且 File API 可用（仅备选权限）→ rename
  else:
    copyStreams(source → target) 
      → 校验 size（必要）/ 可选前 64KB hash
      → 成功后 deleteDocument(source)
      → 失败：删不完整目标，保留源，item=FAILED
```

**流式拷贝：** 8–256KB buffer；更新 `bytes_copied`；支持 cancel（删半成品）。

### 10.3 任务状态机

```text
PENDING → RUNNING → SUCCESS
                 → FAILED（可 RETRY → RUNNING）
                 → CANCELLED
PAUSE：V1.0 可只做 CANCEL；PAUSE 二期
```

WorkManager：`ExistingWorkPolicy.KEEP` 单队列顺序执行 Move，避免磁盘打满；通知栏进度。

### 10.4 与 MediaStore 同步

移动后：

1. 更新 Room；
2. `MediaScannerConnection.scanFile` 或 MediaStore insert（视 URI 类型）；
3. 旧 MediaStore 条目可能残留 → 尽量 `createDeleteRequest` 清理（用户授权）。

### 10.5 安全清单（测试必测）

- 拷到 99% 杀进程：源在、目标半成品应被标记清理；
- 目标空间不足：失败、源在；
- 权限丢失：失败原因可读；
- 覆盖策略误触：文案 + 确认。

## 14. 性能预算与调优清单

### 14.1 目标复述

| 场景 | 目标 |
|------|------|
| 5k 列表滚动 | 接近 60fps |
| 滑动切换 | <500ms 出画/出声 |
| 首次扫描 5k | ≤60s（内部存储） |
| 增量无变更 | ≤5s |
| 滑动内存 | ≤500MB |
| 崩溃率 | <0.5% |

### 14.2 具体手段

1. Paging + 占位缩略图；Coil 内存缓存限额；
2. DB 查询避免 `SELECT *` 大字段；列表用 `VideoListItem` 投影；
3. Compose：`key(videoId)`；避免在 item 读盘；
4. 元数据富化限并发；
5. 滑动：预加载仅 Exo；VLC 单实例；页不可见立即 `pause`；
6. R8 + ABI 过滤；
7. 严格模式 Debug 开检测主线程 IO。

### 14.3 性能验收机型建议

- 中端：骁龙 7 系 / 天玑 8000 类，8GB RAM；
- 低端抽样：4–6GB RAM（强制 preload=1）。

## 22. 附录：核心伪代码

### 22.1 PlayerSessionCoordinator

```kotlin
class PlayerSessionCoordinator(
  private val pool: PlayerPool,
  private val router: PlayerRouter,
) {
  suspend fun onSettled(index: Int, ids: List<Long>, n: Int) {
    val keep = (index - n..index + n).filter { it in ids.indices }.toSet()
    pool.retainOnly(keep)
    keep.forEach { i ->
      val media = repo.getMediaRef(ids[i])
      val engine = pool.getOrCreate(i) {
        // 预加载强制 Exo；当前页才允许 router 完整 failover
        if (i == index) router.obtain(media, settings.prefer)
        else router.obtain(media, EnginePrefer.EXO_ONLY)
      }
      engine.load(media)
      if (i == index) engine.play() else engine.pause()
    }
  }
}
```

### 22.2 Move 单条

```kotlin
suspend fun moveOne(item: TaskItem, target: DocDir, policy: ConflictPolicy): Result {
  val destName = resolveName(item.fileName, target, policy) ?: return Skip
  return when (val op = planMove(item.source, target)) {
    is MovePlan.AtomicMove -> op.exec(destName).onSuccess { rebind(item.videoId, it) }
    is MovePlan.CopyDelete -> {
      val tmp = copyWithProgress(item.source, target, destName)
      if (!verify(tmp, item.size)) { tmp.delete(); return Fail("MOVE_VERIFY") }
      if (!deleteSource(item.source)) return Fail("MOVE_DELETE_SOURCE") // 源删失败：保留两边并标人工处理
      rebind(item.videoId, tmp.uri)
      Ok
    }
  }
}
```
